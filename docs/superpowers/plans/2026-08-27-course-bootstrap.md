# Course Bootstrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold the shared `main`-branch bootstrap for the AI Engineering course repo: a minimal Bun/TypeScript project with `openai` + `dotenv`, a working single-file agent that calls an LLM via OpenRouter using the OpenAI Responses API, and the `CLAUDE.md`/`AGENTS.md` convention docs that every future weekly branch depends on.

**Architecture:** `bun init` provides the package/tsconfig/gitignore skeleton at the repo root; all source code lives under `src/` (this week's `agent.ts` and every later week's code), while config (`package.json`, `tsconfig.json`, `.env*`) and docs (`CLAUDE.md`, `AGENTS.md`, `docs/`) stay at the root. No test framework is introduced — this bootstrap is verified by running the script and reading its output, per the spec's explicit out-of-scope note.

**Tech Stack:** TypeScript, Bun (runtime + package manager), `openai` npm package (OpenAI Responses API), `dotenv`, OpenRouter as the model provider.

**Spec:** `docs/superpowers/specs/2026-08-27-course-bootstrap-design.md`

## Global Constraints

- Language: TypeScript only.
- Runtime/tooling: Bun only (`bun init`, `bun add`, `bun run`) — no npm/yarn/pnpm, no bundler.
- LLM calls MUST use the OpenAI **Responses API** (`client.responses.create`), never `chat.completions.create`.
- LLM SDK MUST be the official `openai` npm package.
- Model provider is OpenRouter — the `OpenAI` client is constructed with a custom `baseURL` and an OpenRouter API key, both read from environment variables via `dotenv`.
- No agent frameworks (LangChain, LlamaIndex, Vercel AI SDK, or similar) — everything hand-rolled.
- No testing framework, linting, or CI in this bootstrap (explicitly out of scope in the spec).
- Every commit happens on `main`, in the repo already initialized at `/Users/aliradmanesh/Courses/AI Engineering Course/codes` (current HEAD: `f97a8ff docs: add course bootstrap design spec`).

### Task 4: Implement `src/agent.ts` and wire up the run script

**Files:**
- Create: `src/agent.ts`
- Modify: `package.json` (add `dev` script)

**Interfaces:**
- Consumes: `OpenAI` from `openai` (Task 2), `dotenv/config` (Task 2), `OPENROUTER_API_KEY`/`OPENROUTER_BASE_URL` from `.env` (Task 3's `.env.example` documents these; a real `.env` must exist locally for the manual test to succeed).
- Produces: a runnable script, invoked as `bun run src/agent.ts` or `bun run dev`.

- [ ] **Step 1: Write `src/agent.ts`**

```typescript
import "dotenv/config";
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: process.env.OPENROUTER_BASE_URL,
});

async function main() {
  const response = await client.responses.create({
    model: "openai/gpt-4o-mini",
    input: "What is the capital of France? Answer in one word.",
  });

  console.log(response.output_text);
}

main();
```

- [ ] **Step 1: Write `CLAUDE.md`**

```markdown
# AI Engineering Course — Repo Conventions

This repo is homework for an "AI Engineering" course. The end goal is to
build a Claude Code clone from scratch, **without any agent frameworks**
(no LangChain, LlamaIndex, Vercel AI SDK, etc.) — the tool-calling loop,
prompt assembly, and memory must be hand-rolled so the underlying
mechanics are fully understood.

## Tech stack

- TypeScript, run and managed with **Bun** (`bun init`, `bun add`, `bun run`)
  — no npm/yarn/pnpm, no bundler.
- LLM calls go through the OpenAI **Responses API**
  (`client.responses.create`), never Chat Completions.
- LLM SDK is the official `openai` npm package.
- Model provider is **OpenRouter**, used as an OpenAI-compatible endpoint
  via a custom `baseURL` (`OPENROUTER_BASE_URL`) and API key
  (`OPENROUTER_API_KEY`), both loaded from `.env` via `dotenv`.

## Branch model

Weekly homework branches stack on top of each other, since later weeks
extend the agent built in earlier weeks:

```
main ──●───────────────▶ (bootstrap only)
        \
         ●──●──●  week-01
               \
                ●──●──●  week-02
```

- `main` holds only the shared bootstrap (project scaffold, docs, base
  `agent.ts`) and never accumulates homework solutions.
- `week-NN` branches from the previous week's branch (`week-01` from
  `main`, `week-02` from `week-01`, ...), carrying forward all prior
  weeks' code.
- Each week's branch is what gets submitted to the instructor.

## Commit convention

Within a week's branch, each discrete step/section of that week's
assignment is its own commit, in the order completed, with a message
describing that step (e.g. "add tool-calling loop", "add file-read
tool"). This gives a readable, incremental history per week.

## Design docs

Architectural decisions are recorded under
`docs/superpowers/specs/` before implementation. See
`docs/superpowers/specs/2026-08-27-course-bootstrap-design.md` for the
bootstrap's design.
```
